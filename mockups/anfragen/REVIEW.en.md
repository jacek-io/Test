# Anfragen (Inquiries) tab, Merkur module – design review and mockups in 3 variants

Source: Figma `EUROMAR-SKETCHES`, page *Merkur* (node `18-1067`), sections *Merkur* (user view) and
*Merkur for Analysts* (analyst view). Ticket: design of the Anfragen tab (implementation FC-1112).

Mockups: a canvas with 22 artboards generated by `build.mjs`; `translate.mjs` produces the English copy
(`out-en/`). Files in `out/` and `out-en/` also open directly in a browser. Canvas pages: **Overview**
(decision matrix), **Variant A · Minimal**, **Variant B · Fund level**, **Variant C · Topic-first**, **Shared fixes**.

## How to read the variants

All three variants contain the unambiguous fixes from the review (items 1, 2, 5, 6 and the missing screens).
They differ only where the review left a decision open (items 3, 4, 7, 8, 9 and the handling of a fund that
already has an entry).

## Shared fixes (page “Shared fixes” + dialogs A3/B3/C3)

1. **Submitted by** – new field in “Record new inquiry” (A: text with suggestions, B: list of Merkur users + free text, C: Name + Institution).
2. **FondsConsult analyst** – editable, defaults to the signed-in person, select from the team (as in the Analyst Tool).
5. **Empty state** – own copy: what the tab is and where entries come from; user version (pointing at the request buttons in the other tabs) and analyst version (CTA “Record first inquiry”).
6. **Small things** – “Korrektur speichern”, “Merkur Privatbank” in the analyst navigation, two different placeholders (Update: *what is out of date*; Follow-up: *what is unclear*), a real question in the Question field.
- **“Message sent to FondsConsult” confirmation** – acceptance criterion; repeats that the entry does not change until the answer is published.
- **“Add question & answer”** – dialog for flow D (adding an exchange to an existing history, optionally linked to the exchange the follow-up refers to).
- Analyst link “+ Neue Anfrage erfassen” removed from the user view (in Figma it appears in the expanded row of the follow-up mockups).
- Internal note “Entwurf – offene Entscheidung” removed from the history.

## Also spotted during the review (beyond the 9 items)

- The **Documents** column is in the empty-state header and in the ticket (6 data points) but disappeared from the populated table – documents were folded under the answer. Decide deliberately (A vs B/C).
- **Date** – unclear whether it is the entry’s creation date or the last activity. Since the default order is “most recent activity”, I suggest the label “last activity” (B/C).
- Not drawn but required by acceptance criteria: confirmation after sending, handling of a fund with an existing entry, dialog for adding an answer, marker in Pre-analysis/Watchlist/Recommendation list in a populated table.
- The sample table has 3 rows – too few to show sorting and pagination; add ~8 rows before showing the client.
- Open with the client: “Anfrage stellen” button in the tab – the layout leaves room next to “Export”.
- All ISINs and names in the mockups are sample data.

## Language

The product UI is German. The English canvas translates the UI labels as well (Anfragen → Inquiries,
Voranalyse → Pre-analysis, Empfehlungsliste → Recommendation list, Rückfrage stellen → Ask follow-up question)
so that the whole thing reads in one language; proper nouns (Merkur Privatbank, FondsConsult, fund names)
are kept. If the English version is meant for the German client, keep the German UI labels and translate
only the notes – `i18n-en.mjs` is the single place to change that.

## Files

- `lib.mjs` – tokens (from Figma: primary `#1167fe`, stroke `#e4e6eb`, background `#f3f5f9`, Inter), icons, navigation, page/dialog shell.
- `screens-list.mjs` – list, expanded entry, sample data, per-variant filters.
- `screens-modals.mjs` – dialogs: new inquiry, correct answer, add question & answer, update/follow-up + confirmation.
- `screens-misc.mjs` – marker in Pre-analysis (+ side panel in C), empty state, overview board.
- `build.mjs` – generates `out/*.dc.html` and `out/canvas.json` (`node build.mjs`).
- `i18n-en.mjs`, `translate.mjs` – English strings and the translation step (`node translate.mjs` → `out-en/`).
